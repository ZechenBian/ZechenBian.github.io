# flow-compute：算出来，再证明它算对了

## 这个 skill 做什么

把“先定验收 → 植入真值 → 试跑测速 → 计算 → 验收 → 结论”串成一条线。它只管顺序、关口和停在哪；每一步怎么做以被调用的 skill 为准。

“调 X”指用 Skill 工具加载 X 并照它做，同时遵守下面的总控协议。技能列表里的名字可能带前缀（例如 `anthropic-skills:acceptance-gate`），按名字找对应的那个。没有 Skill 工具时，直接读那个 skill 的 SKILL.md。BootLoops 的几个 skill 没装时，按表里“退路”一列自己做。

## 总控协议

1. **先看再问。** 开工前先查手上已有的：对话里的文件、记忆里的项目记录、已连接的应用、相关仓库、之前的批示文档。能查到的不问。
2. **一轮一张批示单。** 本轮所有要你拍板的事合成一张单子：逐条编号，每条写推荐和一句理由，你可以逐条批（采纳 / 改后采纳 / 暂缓 / 不做）。被调用的 skill 不再各自停下来问，它们要问的都并进这张单。4 条以内用提问工具，每条一问、推荐项放第一个；更多或要留档，用“逐条批示版”文档，每行一条、带“批示”下拉列；都没有就在对话里编号列出。
3. **原任务保底。** 你原来要的东西照交；提标和扩展只加不换。扩展不扩权限：发送、发布、删除、部署、合并、花钱、建定时任务，都先问。
4. **关口过独立核验。** 只在流水线里写了关口的地方做。派一个没看过过程的子 agent，只给它成品（需要时加原始材料），不给推理、设计说明和别人的意见；它回报成立 / 有洞 / 说不清，并写位置、原因、能否修。每条发现都归入已修、接受风险或需要你决定（并进下一张批示单），就算过关。没有子 agent，就交一段能直接粘贴进新会话的审查提示（只含成品和要查的清单）；这也做不到，就标“未经独立核验”，照常交付。
5. **没人在场时**（定时任务、你说晚点回来、单子半天没人批）：不用提问工具，批示单和进度写进逐条批示版文档（没有文档工具就写成 Markdown 文件）；开头写明取了哪种读法；按推荐项只做可逆的部分，项目最远做到“样本过关口”（学习、游戏类页面就是样本过独立试玩）。私有 Artifact 不算发布；推送到公开仓库、合并、删除、对外发送、超过约两小时或要花钱的计算，都停在决定前。
6. **小任务直通。** 改动小、可逆、不新增页面或版本的事（修一个 bug、加一个按钮、一个快问题、算一个数），不走流程：直接调对应的 skill 或直接做，结尾一句话说明可以走完整流程。
7. **最多两层。** 一个工作流只能以嵌入模式调另一个工作流（可被嵌入的是 flow-ambition 和 flow-compute）。被嵌入的做到交回结果为止：要批的条目并进调用方的批示单，不单独交付，也不再嵌入别的工作流。
8. **状态在文件里，不在上下文里。** 跨轮或跨会话的工作，在批示文档末尾维护一张“进度”表（阶段 · 状态 · 下一步 · 卡在哪），每过一个关口就更新；回来时或上下文被压缩之后，先重新加载本工作流（压缩后它可能被截断或丢掉），再读进度表，从停下的地方接着做。每个阶段开始时重新加载这一阶段要调的 skill，不假设它还在上下文里。
9. **环境不够就交接。** 跑不了代码、读不到数据或进不了仓库时，交一段能直接粘贴进 Claude Code 的提示：目标、材料在哪、方法、验证命令、完成标准。要跑很久的工作，提示里附一个压缩后自动读回进度表的 SessionStart 钩子（matcher 为 compact）。

## 流水线

| 阶段 | 调用 | 退路（没装时） | 关口（过了才进下一阶段） |
|---|---|---|---|
| 0 声明验收 | acceptance-gate 的第 0 步 | 自己写下同样四项 | 留出点、独立路线、门槛（位数或误差）、正负对照，在算之前写进进度表 |
| 1 植入真值 | planted-truth | 用已知参数造一份数据，走完整条流程 | 找回植入的答案；故意损坏的输入（换列、翻符号）被抓住 |
| 2 试跑测速 | timing-discipline | 同代码、同机器、缩小规模试跑 | 耗时估计附一行来源；超过约两小时先改结构 |
| 3 正式计算 | 领域 skill，或直接写代码 | — | 看产出在不在增长，不看日志 |
| 4 验收 | acceptance-gate、independence-bookkeeping；猜常数时加 constant-recognition | 留出点上数一致的位数或误差，加倍精度重跑，故意改错一处看它会不会挂 | CLOSED，或写明缺什么的 OPEN |
| 5 结论 | 检验一个信念：assumption-audit；拆策略收益：residual-edge-analyzer | — | 只写验收过的结论 |
| 6 交付 | reading-budget | — | 每个数字附误差或位数、精度、是否在留出点上 |

领域 skill：回测用 backtest-expert（写回测框架代码本身才用 backtesting-frameworks）；量子用 qutip、pennylane、qiskit；符号和精确算术用 sympy。没有对口的就直接写代码。

## 关口细节

- **第 0 步写定后不改。** 门槛要放宽才能过，就算没过。用来定参数、挑方法的参考值，不能再拿来验收。
- **第 2 步超过约两小时**：先列至少三条改结构的路线（换表示、先做精确约化、用对称性、拆成独立小块、只算回答问题所需的特例），再派一个新上下文的子 agent，用很短的时间回答“有没有更聪明的路线”，结论记进进度表，然后才决定。不靠换大机器、通宵硬跑。
- **第 4 步的复核**按协议第 4 条，交给没参与计算的子 agent：只给它第 0 步的声明、脚本和结果，让它从声明重写一个独立的检查。
- **数字不用形容词。** “吻合良好”要写成“在 3 个留出点上一致 34 位”或“留出期误差 0.8%（门槛 2%）”。

## 标签

- 内部只用两个：**CLOSED**（第 0 步声明的每项都过了，计数写下）和 **OPEN**（写明已确立什么、缺什么）。
- 交给 research-writeup 时：CLOSED 只说明“在所述模型和精度下算对了”，对应四级里的已确立，但只限这个计算本身；模型是否描述现实，按原有的标签另标。OPEN 对不上四级，保留 OPEN 并写缺什么。

## 嵌入模式

被 flow-research 或 flow-discover 调用时，做到第 4 步，把结果、验收台账和脚本位置交回；第 5、6 步由调用方做（协议第 7 条）。

## 没人在场时

最远做到第 2 步，并写好正式运行计划：预计耗时及其来源、要用的算力、要你批的条目。超过阈值的长跑和花钱的算力停在决定前（协议第 5 条）。

## 什么时候不用

- 算一个数、验一行公式：直接算（协议第 6 条）。
- 只想用现成数据检验一个默认结论、计算很轻：直接用 assumption-audit。
- 写回测框架或量子电路代码本身：直接用对应的领域 skill。
- 要写成文稿：用 flow-research，它会在需要时嵌入本流程。
