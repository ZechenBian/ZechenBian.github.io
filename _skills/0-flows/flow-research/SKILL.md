# flow-research：研究问题从提问到成稿

## 这个 skill 做什么

把写、核、验、审、交付串成一条线：research-writeup 或 flavored-notes 负责写，citation-check 核引用（有新颖性声明时加 lit-review），assumption-audit、flow-compute 或 prove-protocol 检验关键结论，独立审稿把关，flavored-notes 的构建脚本出 PDF。每一步具体怎么做，以对应的 skill 为准。

“调 X”指用 Skill 工具加载 X 并照它做，同时遵守下面的总控协议。技能列表里的名字可能带前缀（例如 `anthropic-skills:research-writeup`），按名字找对应的那个。没有 Skill 工具时，直接读那个 skill 的 SKILL.md。BootLoops 的 skill（lit-review、referee-sim、prose-lint、prove-protocol）没装时，按括号里的退路做。

## 总控协议

1. **先看再问。** 开工前先查手上已有的：对话里的文件、记忆里的项目记录、已连接的应用、相关仓库、之前的批示文档。能查到的不问。
2. **一轮一张批示单。** 本轮所有要你拍板的事合成一张单子：逐条编号，每条写推荐和一句理由，你可以逐条批（采纳 / 改后采纳 / 暂缓 / 不做）。被调用的 skill 不再各自停下来问，它们要问的都并进这张单。4 条以内用提问工具，每条一问、推荐项放第一个；更多或要留档，用“逐条批示版”文档，每行一条、带“批示”下拉列；都没有就在对话里编号列出。
3. **原任务保底。** 你原来要的东西照交；提标和扩展只加不换。扩展不扩权限：发送、发布、删除、部署、合并、花钱、建定时任务，都先问。
4. **关口过独立核验。** 只在流水线里写了关口的地方做。派一个没看过过程的子 agent，只给它成品（需要时加原始材料），不给推理、设计说明和别人的意见；它回报成立 / 有洞 / 说不清，并写位置、原因、能否修。每条发现都归入已修、接受风险或需要你决定（并进下一张批示单），就算过关。没有子 agent，就交一段能直接粘贴进新会话的审查提示（只含成品和要查的清单）；这也做不到，就标“未经独立核验”，照常交付。
5. **没人在场时**（定时任务、你说晚点回来、单子半天没人批）：不用提问工具，批示单和进度写进逐条批示版文档（没有文档工具就写成 Markdown 文件）；开头写明取了哪种读法；按推荐项只做可逆的部分，项目最远做到“样本过关口”（学习、游戏类页面就是样本过独立试玩）。私有 Artifact 不算发布；推送到公开仓库、合并、删除、对外发送、超过约两小时或要花钱的计算，都停在决定前。
6. **小任务直通。** 改动小、可逆、不新增页面或版本的事（修一个 bug、加一个按钮、一个快问题、算一个数），不走流程：直接调对应的 skill 或直接做，结尾一句话说明可以走完整流程。
7. **最多两层。** 一个工作流只能以嵌入模式调另一个工作流（可被嵌入的是 flow-ambition 和 flow-compute）。被嵌入的做到交回结果为止：要批的条目并进调用方的批示单，不单独交付，也不再嵌入别的工作流。
8. **状态在文件里，不在上下文里。** 跨轮或跨会话的工作，在批示文档末尾维护一张“进度”表（阶段 · 状态 · 下一步 · 卡在哪），每过一个关口就更新；回来时或上下文被压缩之后，先重新加载本工作流（压缩后它可能被截断或丢掉），再读进度表，从停下的地方接着做。每个阶段开始时重新加载这一阶段要调的 skill，不假设它还在上下文里。
9. **环境不够就交接。** 跑不了代码、读不到数据或进不了仓库时，交一段能直接粘贴进 Claude Code 的提示：目标、材料在哪、方法、验证命令、完成标准。要跑很久的工作，提示里附一个压缩后自动读回进度表的 SessionStart 钩子（matcher 为 compact）。

## 先分流

| 请求 | 主线 | 说明 |
|---|---|---|
| 总结、解释、“X 是怎么回事 / 为什么对”、论文说了什么、X 和 Y 什么关系 | research-writeup | 默认 |
| 指定作者、学派、体裁或难度的笔记、讲义、习题 | flavored-notes | 要“像谁写的”就走这条 |
| 文献或数据里的某个结论站不站得住 | 先检验（第 5 步），结论并入 research-writeup 的主线 | 没有原始材料就直接讨论，不走本流程 |
| 要证明或证伪一个数学命题 | prove-protocol 跑证明，判定回填 research-writeup 的主线 | 没装：先找反例，再证，由没写过证明的子 agent 从命题出发复核 |
| 多源的市场、行业、趋势调研 | — | 用 deep-research，不走本流程 |
| 一个记号或公式怎么用 LaTeX 写 | — | 直接用 latex-helper（协议第 6 条） |

## 流水线

下面的默认值（四问纲领、核验预算 10 条、命题台账和引用台账放附录、交付前清单）是 research-writeup 的。主写是 flavored-notes 时，规格换成风味卡，结构、核验预算、台账位置和交付说明都按 flavored-notes。

1. **规格。** 一行报默认规格：读者档位、四问纲领、核验预算 10 条、Markdown + PDF。
2. **写之前的批示单（只在需要时）。** 规格真有歧义（例如分不清要总结还是要笔记）、要提标（你说“做深”“按顶尖标准”，或成稿要公开发表时，调 flow-ambition 的嵌入模式）、或要检验结论（方案选择放进单里）时，动笔前出一张单，批完再写；都没有就报完规格直接写。用 assumption-audit 的，先按批过的方案切好并封存留出集，之后写作和检验都不碰它。批了的提标条目在对应步骤里做：层级和标准进第 3 步，检验进第 5 步，团队和红队进第 6 步。
3. **写第一版。** 检验结论的路线先做第 5 步，再用检验结果写。主写 skill 出一页摘要加主线。四问（想干什么 / 为什么可以这么做 / 为什么要这么做 / 有什么结果）是全文的纲领，不是每节的模板。
4. **核引用。** 调 citation-check，按预算核，台账放进附录。成稿里有“首次”“新”一类的新颖性声明时，再调 lit-review 做新颖性审计（没装：近邻文献读全文、正反两个方向追引用、写明哪些范围没查）。
5. **检验（有材料时）。** 对主线里一两个最关键的结论：只需重新分析现成数据的，调 assumption-audit；要跑模拟、回测、拟合或高精度数值的，以嵌入模式调 flow-compute，拿回验收台账，标签按它的映射写；要证明的，见分流表。结论和标签回填主线。
6. **独立审稿（关口）。** 用 research-writeup 的独立审稿，或 flavored-notes 的审稿与风味盲测。成稿要对外（投稿、公开发布）时，审稿之后在新上下文里跑 referee-sim：为每个声称的受众各出一条正确性、一条新颖性的最强质疑，查答案是否出现在标题、摘要、图和结论里；prose-lint 可选。每条发现都归入已修、接受风险或需要你决定，就算过关；做不了审稿，就标“未经独立审稿”，照常交付。
7. **交付。** 用 flavored-notes 的构建脚本出 PDF 和 Markdown。交付说明附上交付前清单、核验数、审稿结果，再用一句话列可以追问的方向。
8. **追问生长。** 追问的回答给在对话里；超过一屏或自成一节的写进附录，新命题进台账，需要时补核引用，重出 PDF，版本号加一。

## 什么时候不用

- 只问一个定义、一个记号、一个快问题：直接回答，或直接用对应的 skill。
- 只要一份总结或笔记、不需要检验也不需要提标：直接用 research-writeup 或 flavored-notes，它们自带核引用、审稿和 PDF。
- 多源的市场与趋势调研：用 deep-research。
- 只要一个验收过的数字、不写成稿：用 flow-compute。
