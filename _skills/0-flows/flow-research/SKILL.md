# flow-research：研究问题从提问到成稿

## 这个 skill 做什么

把写、核、验、审、交付串成一条线：research-writeup 或 flavored-notes 负责写，citation-check 核引用，assumption-audit 用原始材料检验关键结论，独立审稿把关，flavored-notes 的构建脚本出 PDF。每一步具体怎么做，以对应的 skill 为准。

“调 X”指用 Skill 工具加载 X 并照它做，同时遵守下面的总控协议。技能列表里的名字可能带前缀（例如 `anthropic-skills:research-writeup`），按名字找对应的那个。没有 Skill 工具时，直接读那个 skill 的 SKILL.md。

## 总控协议

1. **先看再问。** 开工前先查手上已有的：对话里的文件、记忆里的项目记录、已连接的应用、相关仓库、之前的批示文档。能查到的不问。
2. **一轮一张批示单。** 本轮所有要你拍板的事合成一张单子：逐条编号，每条写推荐和一句理由，你可以逐条批（采纳 / 改后采纳 / 暂缓 / 不做）。被调用的 skill 不再各自停下来问，它们要问的都并进这张单。4 条以内用提问工具，每条一问、推荐项放第一个；更多或要留档，用“逐条批示版”文档，每行一条、带“批示”下拉列；都没有就在对话里编号列出。
3. **原任务保底。** 你原来要的东西照交；提标和扩展只加不换。扩展不扩权限：发送、发布、删除、部署、合并、花钱、建定时任务，都先问。
4. **关口过独立核验。** 只在流水线里写了关口的地方做。派一个没看过过程的子 agent，只给它成品（需要时加原始材料），不给推理、设计说明和别人的意见；它回报成立 / 有洞 / 说不清，并写位置、原因、能否修。每条发现都归入已修、接受风险或需要你决定（并进下一张批示单），就算过关。没有子 agent，就交一段能直接粘贴进新会话的审查提示（只含成品和要查的清单）；这也做不到，就标“未经独立核验”，照常交付。
5. **没人在场时**（定时任务、你说晚点回来、单子半天没人批）：不用提问工具，批示单和进度写进逐条批示版文档（没有文档工具就写成 Markdown 文件）；开头写明取了哪种读法；按推荐项只做可逆的部分，页面类项目最远做到“样本过独立试玩”。私有 Artifact 不算发布；推送到公开仓库、合并、删除、对外发送，都停在决定前。
6. **小任务直通。** 改动小、可逆、不新增页面或版本的事（修一个 bug、加一个按钮、一个快问题），不走流程：直接调对应的 skill 或直接做，结尾一句话说明可以走完整流程。
7. **记进度。** 跨轮或跨会话的工作，在批示文档末尾维护一张“进度”表（阶段 · 状态 · 下一步 · 卡在哪）；回来时先读它，从停下的地方接着做。
8. **环境不够就交接。** 跑不了代码、读不到数据或进不了仓库时，交一段能直接粘贴进 Claude Code 的提示：目标、材料在哪、方法、验证命令、完成标准。

## 先分流

| 请求 | 主写 | 说明 |
|---|---|---|
| 总结、解释、“X 是怎么回事 / 为什么对”、论文说了什么、X 和 Y 什么关系 | research-writeup | 默认 |
| 指定作者、学派、体裁或难度的笔记、讲义、习题 | flavored-notes | 要“像谁写的”就走这条 |
| 文献或数据里的某个结论站不站得住 | assumption-audit 先检验，结论并入 research-writeup 的主线 | 没有原始材料就直接讨论，不走本流程 |
| 多源的市场、行业、趋势调研 | — | 用 deep-research，不走本流程 |
| 一个记号或公式怎么用 LaTeX 写 | — | 直接用 latex-helper（协议第 6 条） |

## 流水线

1. **规格。** 一行报默认规格：读者档位、四问纲领、核验预算 10 条、Markdown + PDF。
2. **写之前的批示单（只在需要时）。** 有下面任何一种情况，动笔前先出一张单，批完再写：规格真有歧义（例如分不清要总结还是要笔记）；要提标（你说“做深”“按顶尖标准”，或成稿要公开发表时，调 flow-ambition 的嵌入模式，它的条目放进这张单）；要用 assumption-audit 检验结论（它的方案选择放进这张单）。都没有，就报完规格直接写。
3. **写第一版。** 主写 skill 出一页摘要加主线。四问（想干什么 / 为什么可以这么做 / 为什么要这么做 / 有什么结果）是全文的纲领，不是每节的模板。
4. **核引用。** 调 citation-check，按预算核，台账放进附录。
5. **检验（有原始材料时）。** 按批过的方案，对主线里一两个最关键的经验结论调 assumption-audit；它的结论和标签回填主线。
6. **独立审稿（关口）。** 用 research-writeup 的独立审稿，或 flavored-notes 的审稿与风味盲测。每条发现都归入已修、接受风险或需要你决定，就算过关；做不了审稿，就标“未经独立审稿”，照常交付。
7. **交付。** 用 flavored-notes 的构建脚本出 PDF 和 Markdown。交付说明附上交付前清单、核验数、审稿结果，再用一句话列可以追问的方向。
8. **追问生长。** 追问的回答给在对话里；超过一屏或自成一节的写进附录，新命题进台账，需要时补核引用，重出 PDF，版本号加一。

## 批示单示例（第一版交付时）

| 编号 | 事项 | 推荐 | 理由 |
|---|---|---|---|
| 1 | 审稿发现“物理论证写成了已证”（第 3 节） | 改标签 | 数学那边只有特殊情形的证明 |
| 2 | 未核实的 2 条引用 | 再核 2 条 | 都在主线里 |
| 3 | 下一步展开哪个方向 | 第 2 个方向 | 和你上次追问的问题相连 |

## 什么时候不用

- 只问一个定义、一个记号、一个快问题：直接回答，或直接用对应的 skill。
- 只要一份总结或笔记、不需要检验数据也不需要提标：直接用 research-writeup 或 flavored-notes，它们自带核引用、审稿和 PDF。
- 多源的市场与趋势调研：用 deep-research。
