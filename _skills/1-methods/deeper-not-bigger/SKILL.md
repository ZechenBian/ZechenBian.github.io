# deeper-not-bigger：把任务做深，而不是做大

来源：Felix Rieseberg《How to be more ambitious: A tutorial for humans with models》中的「深度」。核心是让 Claude 用这个领域最好的从业者会用的材料、方法和标准来做事，一直推进到连这些专家也可能从结果里学到东西。

## 何时用

- 用户说「做深一点」「做到专业水准」「按顶尖的标准来」，或在交任务之前要求提高标准。
- 用户给了一个任务，而直接去做只会得到一个「看起来专业」的结果。

不用：用户只要一个快速答案；或者任务很小，一句话就能说清要改什么。

## 与其他 skill 的关系

- **在 altitude 之后、assemble-the-crew 之前**：先定做到哪一层，再定标准和裁判，最后才决定要哪些领域。
- **让给**：只想知道一个默认结论站不站得住 → assumption-audit；要多个领域一起看 → assemble-the-crew。
- **由 flow-ambition（或调用它的 flow）编排时**：第 3 步的重写版并进它的批示单，不单独停。
- **小任务**：按上面“不用”的情形，直接做，结尾一句话提一下可以按顶尖标准做完整版。

## 原任务保底

重写版必须覆盖原任务的全部明确要求（文件、格式、截止时间、口径），逐条写进去；做深只加不换。扩展不扩权限：发送、发布、删除、部署、花钱，都先问。

## 流程

### 第 1 步：先看已有的，再回答四问

先看对话里的文件、已连接的数据源、相关仓库和记忆里的记录：顶尖从业者会用的原始材料，很多时候已经在手边。然后针对用户的任务逐条回答，每条写具体名称，不写形容词：

1. 这个领域顶尖的从业者在这里会做、而用户没有要求的事是什么？
2. 他们会从哪种最原始的材料入手（原始数据、日志、一手文献、源代码、原始记录），而不是别人已经消化过的摘要或报表？
3. 他们会用哪些具体的方法和工具？再补一问：别的领域有没有解决同类问题的更好工具，可以借过来用？
4. 除了 Claude 和用户自己之外，什么能证明结果是对的？例如测试、留出数据、可复现的计算、独立来源、现实世界的检验。

### 第 2 步：定目标——人类已知的最好水平

- 根据用户的要求，估计这件事在人类已知范围内的最好水平：顶尖从业者或最好的公开结果做到了什么程度。
- **依据必须可查**：写出处（论文、公开榜单、官方数据、可复现的公开结果），附链接。查不到就写「未找到可查的先例」，再给出自己的估计和不确定在哪里。不用「通常」「业内一般」「成熟团队」这类说法代替出处：它们读起来像依据，其实没有。
- 把这个水平定为目标，并明确写出「这个目标可以达到」。
- 执行中如果判断「做不到」，先换方法继续推进，不要自行降低目标。确实被环境卡住时，说清楚卡在哪一步、缺什么。

### 第 3 步：交出重写版，等用户确认

输出以下四部分，然后停下：

1. 四问的答案（简短）。
2. 目标及其依据。
3. 重写后的任务提示。
4. 外部验证的方式。

在用户确认或修改之前，不要开始执行。由 flow 编排时，这四部分交给它，并进它的批示单。

### 第 4 步：执行（用户确认后）

- **先量基线，冻结裁判。** 动手前用确认的外部验证方式量一次现状；把裁判（测试、留出数据、评测脚本）固定下来，执行期间不改它。要改裁判，先停下来说明原因，由用户决定。
- 检查方法是否真的换了：如果确认的方法是数据库、统计模型或仿真，就不能交出一张 markdown 表格。只换了措辞、没换方法，等于没有完成。
- 当前环境不能跑代码或读数据时，输出一段可以直接粘贴进 Claude Code 的实现提示，写清楚：目标、原始材料在哪里、要用的方法、基线怎么量、验证命令、完成标准。
- 交付时汇报「目标 vs 实测」：基线、目标、实测各一个数，加上裁判是什么、跑了什么。没有外部验证的部分，明确标注「未经外部验证」。

### 第 5 步：沉淀

任务结束后，如果这次用到了今后很可能反复用到的专家工具或方法（尤其是从别的领域借来的），把它们列出来，问用户要不要加进本 skill 的「常用专家工具」一节。用户同意后，以更新本 skill 的方式提交完整的新版 SKILL.md。

## 没人在场时

第 1、2 步照做并写出重写版；第 4 步只做可逆的部分（量基线、搭验证），开头写明按哪个版本推进；对外动作和不可逆的步骤停在决定前。

## 常见失败

- 只换词汇：自称「资深数据科学家」，却仍然用肉眼看表格。
- 目标保守：模型自己把目标调低。
- 依据靠「通常」「业内」顶替出处。
- 自评：用「我检查过了」代替外部验证。
- 执行中悄悄改了裁判，或者没有先量基线。
- 做大不做深：加更多页数、更多功能，而不是换更好的材料和方法。
- 角色扮演：模仿专家的口吻，而不是做专家实际会做的事。

## 简短示例

用户：「帮我分析一下用户为什么流失。」

- 四问：(1) 顶尖分析师会按获客时间分组看留存曲线，而不是只看总流失率；(2) 从原始事件日志入手，而不是月度报表；(3) 队列分析、生存分析、按渠道分层，并考虑借用医学里的生存分析方法；(4) 用最近一个季度作留出数据，检验找到的信号能否预测流失。
- 目标：找到比现有指标更早出现的流失信号，提前量至少是现有指标的两倍，并在留出数据上验证。依据：未找到可查的公开基准（各产品的流失机制差别很大），所以先在用户过去一年的数据上量出现有指标的提前量，作为基线。
- 然后交出重写后的提示和验证方式，等用户确认。
