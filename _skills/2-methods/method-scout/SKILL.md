# method-scout：从方法出发找题

## 这个 skill 做什么

很多领域卡在一个计算上，而别的领域早有方法能直接解它，只是没人跨过去。本 skill 从你手上的方法出发，去别的领域找这样的计算，判断能不能做、能不能验，交一组候选卡。

它不判断题目有没有意思。那是你和领域专家的事；它只把判断要用的材料备好。

## 与其他 skill 的关系

- kickoff-assessment 评估一个已有的想法；flow-ambition 往上抽一层；本 skill 从方法出发找想法。
- 新颖性由 flow-discover 在选题前对排前几的卡核（lit-review；没装就近邻文献读全文、正反两个方向追引用）；单独使用时不核，卡上标“未核新颖性”。开算用 flow-compute。
- 一般由 flow-discover 调用；单独用时做到候选卡为止，你选定并有了结果后再出专家包。

## 流程

1. **把方法写成结构。** 方程或积分的形式、算法类别、需要什么输入、对多大的规模可行；再列 3–6 条结构不变量（迁移到别处时必须仍然成立的东西）。
2. **按学科表扫邻域。** 按 Semantic Scholar 或 OpenAlex 的学科分类逐个领域找同形的对象；同一个对象在别的领域常换了名字，同义词逐个搜。每个候选都要读到原文证据：对方文献里写明这个计算卡住了（只能近似、只能 Monte Carlo、只算了小规模、长期未解）。凭记忆的不算。
3. **逐条核结构不变量。** 每条写 PASS 或 FAIL 和一句理由；有一条 FAIL 就淘汰，或写明要怎样改造。领域距离标近 / 中 / 远；远距离的迁移放上批示单，由你拍板。
4. **四项打分（每项 0–2）。** 可核验：有没有独立路线、可复现的已发表数字或留出数据。AI 抓手：对方领域没人知道的工具、跨领域知识、大规模机器阅读、穷举、代码质量。新可能：是以前做不了的，还是只是更快、位数更多。数据现成：数据是否公开可得。可核验为 0 的排到最后。
5. **纠偏。** 压低“被高引、但早被遗忘的旧争论”；每张卡写一句“这个领域已经定性知道什么”，预判专家看到时会不会耸肩。
6. **出候选卡。** 5–10 张，先按可核验、再按总分排序。

## 候选卡

| 字段 | 写什么 |
|---|---|
| 问题 | 一句话 |
| 卡在哪 | 对方原文的出处和位置（可点开） |
| 我方方法 | 用什么、为什么同形 |
| 不变量 | PASS / FAIL 计数；领域距离 |
| 打分 | 可核验 / AI 抓手 / 新可能 / 数据现成 |
| 已经知道什么 | 该领域定性已知的结论 |
| 头号风险 | 最可能失败的地方 |
| 要问专家的一个问题 | 一句话 |

## 选定之后：专家包

你选定一张卡、并且有了验收过的结果（来自 flow-compute）之后，出三样东西：

1. **一页专家包**：算了什么、过了哪些关口、Claude 认为的意义、该领域已经知道的东西。
2. **改题预演**：三种常见方向各写一句可能的收益——减去零模型、研究残差；从单个量换到成对或相关的量；换到该领域最受关注的数据集。
3. **给专家的短邮件草稿**：两三个具体问题，附可复现脚本的位置。只起草，发不发由你决定。

## 没人在场时

开头写明取了哪种读法（方法的哪种表述、扫了哪些领域）；做到候选卡为止：不选题、不开算、不发邮件。

## 边界

- 分数只用于排序，不等于推荐。
- 没有可核验路线的候选，不推荐开算。
- “卡在哪”的证据和所有引用都要能点开核对。
