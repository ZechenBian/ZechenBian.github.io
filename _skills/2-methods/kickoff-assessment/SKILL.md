# 项目启动评估

## 为什么有这个 skill

用户的习惯是先评估再拍板。这一步的价值在于结构稳定、判断诚实、篇幅可控：用户要的是能拍板的依据，不是热情的方案书。

## 与其他 skill 的关系

- **先于** lab-builder（选 A 之后才开工），也先于 altitude 和 deeper-not-bigger（先定做不做，再谈做多大、多深）。
- **让给**：已经决定要做、只差动手 → lab-builder；要的是“这件事背后要什么结果”而不是一个新项目 → altitude；要检验一个已有的说法或结论 → assumption-audit。
- **一轮只停一次**：单独使用时，评估、假设和要你决定的事放在同一张单子上，一次给出；不自行串接其他方法，要串就用 flow-project 或 flow-ambition。
- **由 flow-project 编排时**：结尾的 A / B / C 并进它的批示单，不单独停。
- **快速判断**：用户明确只要快速判断（“一句话说说靠不靠谱”）时，只给三行（定位、最大风险、最小样本）。用户说“先评估”，或由 flow-project 调用时，一律出完整评估。

## 开始前

- 先看已有的：对话里的文件、记忆里的项目记录、已有的实验室（仓库或 Artifact 列表）、已连接的应用。能查到的不问。
- 从对话里提取：目标用户、核心玩法或用途、形态（页面 / agent / 工具 / 网站）、和已有项目的关系。
- 缺的信息不要一条条追问，也不先停下来问：写成“假设”列在开头，让用户纠正；真正决定性的那一个，放进结尾的单子，和 A / B / C 一起问。

## 两个模式

- **评估**（默认）：按下面的固定结构写。
- **压力测试**（用户说“攻击它”“压力测试”“挑毛病”）：只找可能致命的问题，每条写“为什么致命”和“怎么检验”，不附改法、不说优点，直到用户说“结束攻击”或要求改方案。结尾仍是 A / B / C。

## 固定输出结构

### 1. 一句话定位
它是什么、给谁、玩或用一次大约多久。

### 2. 核心循环或使用场景
- **游戏、互动页**：每一轮用户做什么 → 得到什么反馈 → 为什么想再来一轮。写不出“为什么想再来一轮”就是可玩性红灯，直说。
- **agent、研究工具、网站**：它替代哪种现有做法；谁会每周用、在什么场景下用；成功看什么指标（一两个能量化的）。写不出“谁每周用”就是价值红灯，直说。

### 3. 技术可行性
- 需要的 AI 调用：每轮几次、延迟多少、成本量级。价格先查官方定价页，写来源链接和查询日期；查不到就写“未查到，按 × 估”。
- 内容真实感：文字 / 图片 / 视频各自的实现难度、延迟和效果，用表格比。
- 数据来源与许可。
- 在用户现有形态（单文件静态页、GitHub Pages、无服务器）下能不能做；做不了的部分需要什么。

### 4. 价值与差异
- 和已有项目的关系：独立页面还是并入；并入的话放在哪一层。
- 同类产品先检索，不凭记忆：找两三个，各附链接和检索日期，说明差异点是不是真的差异。

### 5. 最小样本
第一个可以给用户审的东西，具体到“一关 / 一个场景 / 一个 agent 回合”，以及做它要多少模型时间、用户要提供什么。

### 6. 头号假设与风险
- **头号假设**：最可能让整件事不成立的那一个假设，配一个最小验证，最好能在样本里顺带完成。
- 另外三条最可能让它失败的原因，每条配一个可检验的放弃条件（“样本做出来后如果 ××，就停”）。

### 7. 分期
样本 → 第一版 → 扩展，各期范围一句话。另列“暂缓”：明确先不做的部分和理由。

### 8. 结尾
有决定性的问题时，先列出它（附推荐的答案），再写固定的结尾句：**未开工。等你决定：A 做样本 / B 改方案 / C 放弃。**

## 判断标准

- 可玩性看三件事：选择是否有意义（不同选择导向不同结果）、反馈是否及时清晰、学习曲线是否平滑。
- 工具和 agent 看三件事：替代的做法是否真的痛、使用频率、成功指标能不能测。
- “用 AI 实时判定”的方案要单独评估失败模式：判定不一致、被玩家绕过、延迟破坏节奏。
- 诚实优先：不靠谱就说不靠谱，并给出“改成什么样会靠谱”。

## 没人在场时

单独使用时（定时任务里，或用户说晚点再看）：照常写完评估，结尾的 A / B / C 标出推荐项和理由，不开工。由 flow-project 或 lab-builder 调用时，按调用方“没人在场时”的规则推进。

## 篇幅与形式

- 在对话里回答，除非用户要文档；全文一到两屏。
- 不写代码、不建文件、不画原型。用户说“开始做样本”之后，交给对应的建造 skill（页面类用 lab-builder），或由 flow-project 接着推进。
