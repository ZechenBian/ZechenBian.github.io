# altitude：多问一句「然后呢」

来源：Felix Rieseberg《How to be more ambitious》中的「高度」，加上他在播客里讲的「往上抽一层、让这件事以后再也不用做」。交给模型的任务，往往只是用户对「怎样得到想要的结果」的一个猜测；往上走一层，就是直接对结果负责。

## 何时用

- 用户交来一件具体的事，而它显然是为了某个更大的结果：准备会议材料、写一份周报、每周重复的导出或整理。修 bug、整理数据这类事，只在用户说「往上抽一层」或结果明显要拿去开会时才用。
- 用户说「往上抽一层」「这件事怎么才能不用每次都做」。

提示（不作门槛）：这件事之后会不会被拿去开会讨论？会的话往往很适合。创意类任务（写小说、做设计）通常不适合往上抽，提醒用户之后按用户的意见办。

## 与其他 skill 的关系

- **先于** deeper-not-bigger、assumption-audit、assemble-the-crew：先选做到哪一层，再定标准、检验和团队。
- **让给**：还没决定做不做的新项目 → kickoff-assessment。
- **一轮只停一次**：单独使用时，目标推断、四层阶梯和推荐层放在同一张单子上，一次给出；不自行串接 deeper-not-bigger 等方法，要串就用 flow-ambition。
- **由 flow-ambition（或调用它的 flow）编排时**：不单独停下，把阶梯和推荐交给它，并进同一张批示单。
- **小任务**：一两句话能说清、做完没人会拿去开会的事，不展开阶梯，直接做，结尾一句话提一下可以往哪里抽。

## 原任务保底

无论选哪一层，原来要的东西照交；往上抽只加不换。原任务明确、可逆、用不了多久时，先把它做完，和阶梯一起交。扩展不扩权限：发送、发布、删除、部署、合并、花钱、建定时任务，都先问。

## 流程

### 第 1 步：先看已有的，再问目标背后的目标

- 先看：对话里的文件、记忆里的相关记录、已连接的应用和数据源。能查到的不问。
- 目标背后的目标：这件事做完之后，用户希望发生什么？谁会用它、用来做什么决定？信息够就写出你的推断；不够就把这个问题作为第 3 步那张单子的第 1 条。不单独先停下来问。

### 第 2 步：给出四层阶梯

每层写清五项：做什么、产出什么、需要什么材料或权限、工作量、裁判。

- **工作量**写成“模型时间 + 用户要提供什么”（数据、权限、一次会议、一个决定），不写人天。人天是按没有模型时的经验估的，会把方案往下压；真正耗时的常常是用户那边的权限和数据。
- **裁判**：什么能证明这一层做成了，而且不是模型自评，例如测试、留出数据、下一期结果的复盘、一位真人的检查。写不出裁判的层不推荐，推荐退到下一层。

1. **完成任务**：按原样把事做好。
2. **回答背后的问题**：尽量多拿原始材料，回答「变了什么、为什么、该怎么办」，并列出最紧迫的几项决策，每项附正反两方面的论证。
3. **重新设计流程**：指出这件事存在的真实目的，设计一个比现有流程更好的机制；用历史数据回测它能否更早或更好地达到这个目的；建议与旧流程并行试运行一段时间。
4. **长期自动运行**：让这件事以后不再需要人去发起，例如定时任务、实时更新的页面、自动从邮件或数据源抓取。

### 第 3 步：推荐一层，附首个探针

- 推荐一层并说明理由。
- **首个探针**：在推荐层旁边写一个几分钟到半小时内能做完的最小一步，用来验证这一层走不走得通。探针失败就退一层。
- 目标推断、阶梯和推荐一起给出，由用户确认推断、决定做哪一层。

### 第 4 步：执行所选的层

- 第 1 到 3 层：直接执行。当前环境跑不了代码或读不了数据时，给出一段可以直接粘贴进 Claude Code 的实现提示。
- 第 4 层：只列出需求和方案，不自行创建。写清楚需要哪些基础设施，例如数据访问、版本或记录的对应关系、能复现和验证结果的环境、触发条件和频率。用户同意后，才创建定时任务或实时页面。

## 没人在场时

按推荐层做可逆的部分（探针、分析、草稿），开头写明取了哪一层、为什么。第 4 层的定时任务、实时页面和一切对外动作都停在决定前。

## 示例

任务：「帮我把这季度的数字填进 QBR 模板。」

- 目标背后的目标：让管理层及早发现问题，把钱和人调到对的地方。
- 四层：
  1. 填模板。裁判：数字和源表逐项一致。
  2. 用全部数据解释变化，并列出三个最紧迫的决策。裁判：下季度复盘这些决策的结果。
  3. 设计一个比季度幻灯片更早发现问题的机制，用过去两年的数据回测，再与下个季度的 QBR 并行跑。裁判：回测里提前发现的周数。
  4. 让它每周自动更新成一个实时页面（只列方案，经同意后再建）。
- 推荐第 2 层。首个探针：用上季度数据试写一条“变了什么、为什么”，半小时内看能不能落到具体原因。

## 常见失败

- 跳过第 1 步，直接按字面意思去做。
- 抽得太高（「帮公司赚钱」），给不出可执行的产出，也找不到裁判。
- 未经同意就创建定时任务或自动化。
- 对创意类任务硬套阶梯。
- 往上抽之后，原来要的东西没交。
