# Deep Learning Lab · 深度学习实验室

Tony Feng 的课程 Math 270 “A Survey of Deep Learning for Mathematicians”（UC Berkeley，2025 年秋）的**非官方学习伴侣**：在一个页面里读笔记、就任何一行提问、在自己的 Mac 上训练模型并核对自己的预测。

- 课程主页：<https://math.berkeley.edu/~fengt/2025F_270.html>（2026-11-10 读取）。课程的讲义、幻灯片、Colab 都是 Tony Feng 和他学生的作品；本页面只链接、不转载，记号沿用讲义（行向量）。
- 页面语言：英文（课程和提问都是英文）。
- 源码：`src/`；构建：`node build.js` → `index.html`（单文件）；`node build.js --artifact <路径>` 另出一份发到 Claude Artifact 的变体（去掉文档骨架）。KaTeX 从 `../strategy-lab/node_modules` 取（先在 `strategy-lab/` 里 `npm install`）。
- 测试：`node test/e2e.js`（见下）；参考运行：`python3 test/make_reference.py`。

三个入口：

- **Read**：笔记。每条陈述带标签（Theorem / Heuristic / Empirical / Contested / Convention），证明折叠。课程地图里列出当前单元的各节，滚动时标出正在读的那一节；笔记和解释里的 “section 6” 是链接；窄屏上是一个折叠的目录。重载后回到上次读到的位置。
- **Ask**：选中任何文字 → Ask。回答留在右边的“页边”，挂在那一段上（R1、R2…），先短后长，可追问，可搜索；一字不差的重复提问直接打开原来那条，相近的会被列出来。
- **Train**：每个实验先让读者预测，再在读者自己的 Mac 上跑（或看记录下来的参考运行），页面用这次运行自己的数字判定哪个选项成立，并讲原因。第一次的预测记入 Prediction ledger。脚本一旦被改过，运行就是“自由运行”：不预测、不判定（问题问的是原脚本）。引擎里没有 PyTorch 时，PyTorch 实验不给运行按钮，直接给参考运行并说明怎么装。

### 第 3 周起（2026-11-11 起，逐周铺开）

规则和第 2 周相同：样本规则不变，不重新评估，不开子代理，**没有独立试玩**。每写完一周单独提交、推到 `deep-learning-lab/remaining-weeks`，并更新试写的 Artifact。实验只用 numpy（这个容器里装不了 PyTorch，也录不了 Mac 上的参考运行）。`node test/seed_audit.js 40 u03` 这样只审计一周的实验。

- 第 3 周：`u03_estimators`（方差用 n − 1、n、n + 1 做除数，哪个 MSE 最小——n + 1；James–Stein 在十维里比 X 本身好多少——误差约为 0.62 倍）；`u03_losses_priors`（Laplace 噪声下 LAD 与最小二乘的斜率误差之比约 0.65；50 个系数 60 个观测时 MAP 岭回归的误差约为最小二乘的 0.16 倍）。
- 第 5 周：`u05_shifted_motif`（图案只在左半边训练，测试放到右半边：全连接网络约 50%，即瞎猜，卷积网络约 97%）；`u05_residual_depth`（学一个接近恒等的映射：32 块普通网络的训练损失约为 4 块的 60 倍，还不如直接输出 x；32 块残差网络约 0.0001）。为了给这个实验找到稳定的现象试了三种设定，记在提交说明里。
- 第 6 周：`u06_long_memory`（初始化时普通 RNN 第一步的梯度比最后一步小 100 倍以上，跨种子在 1e-14 到 3e-4 之间；加法单元学会 60 步延迟，准确率 100%。普通 RNN 有时也能学会——Adam 部分抵消了梯度消失——所以没有拿它的准确率出题）；`u06_decoding`（贪心解码陷入循环，只有约 4% 的 8 字符窗口互不相同；束搜索的输出每字符 0.517 比特，真实文本 1.95 比特）。

### 第 2 周是怎么做的（2026-11-10，试写）

按“铺开”阶段的规则写，样本的规则不变；没有重新评估、没有改样本，也**没有做独立试玩**，上面两轮试玩都不覆盖这一周。

- 动手图 `codelen`：四个字母、40 个字母的消息（频率与信源完全一致，顺序固定），读者拖柱子定模型概率，消息按每个字母 $-\log_2 q$ 比特铺成一条，一格一比特。要读者自己发现：模型等于频率时最短（熵）、把某个字母的概率压向 0 代价无上界、均匀信源谁也打不过 2 比特。笔记第 1、3、4 节再给这些起名字（熵、KL、Gibbs）。
- 实验 `u02_arithmetic_coding`（模拟）：用 Python 整数做的精确算术编码器，编码后再解码核对。三个问题：每字母比特数（约 0.08，远低于逐字母编码的 1）；码字比各字母惊奇度之和多几比特（总共不到 2）；模型错 10 倍时低估与高估哪个浪费多（约 2 倍之差，即 KL 不对称）。
- 实验 `u02_shakespeare_ngrams`（真实，Tiny Shakespeare，和第 7 周同样的 90/10 切分）：按上下文长度 0–9 估计条件熵，一种是在训练文本上直接代频率（plug-in），一种是 Witten–Bell 平滑后在留出文本上的交叉熵；再列 zlib / bz2 / lzma 作参照。两个问题：plug-in 在 k = 9 时只有 0.366 比特（低于 Shannon 对英语的估计，因为一半以上的位置的上下文只出现一次）；留出的代价先降后升（k = 4 时最低 2.408，k = 9 时 2.954）。这个实验不用随机数（只有最后的生成样本用），所以换种子答案不变。
- 测试工具的改动只为这个单元：`test/run_local.py` 新增 `local_data()`，脚本里有 `lab.dataset("tinyshakespeare")` 时从 `data/` 读出来随任务发给引擎（`make_reference.py`、`seed_audit.py` 和命令行都用它；构建机不能联网）；`make_reference.py` 可以只重录指定前缀的实验（`python3 test/make_reference.py u02`），其余条目原样保留——这次就是这样录的，第 1、4、7 周的参考运行逐字节未变。
- 共享模块的改动：`app.js` 里“第 1、4、7 周写完了”“七个实验”两处原本是写死的，改成按 `course.js` 的 status 和实验数生成。
- 没有核对的：参考文献是凭记忆写的，没有逐条对出处；讲义 §2 的记号没有对照（笔记用 $\log = \log_2$、$H$、$D(p\,\|\,q)$、$I(X;Y)$ 的通用写法）。

引擎只认识 `supervised` / `forecast` 两种任务。自由实验借 `supervised` 运：数据是三行占位数据，代码是“读者的脚本 + `src/labrt.py`”，`labrt.py` 的 `fit()` 调脚本的 `run(lab)`，`inspect()` 把脚本交给 `lab` 的全部东西作为一个 JSON 字符串带回来（`result.internals.extra.json`）。运行时接在脚本后面，所以报错的行号就是读者看到的行号。页面不在读者的电脑上安装或保存任何东西；数据集（Tiny Shakespeare）随任务发给引擎，只在内存里。

## 数据标签

- **真实**：Tiny Shakespeare（`data/tinyshakespeare.txt`，1,115,394 个字符，65 种）。来源：Andrej Karpathy 的 char-rnn 仓库 <https://github.com/karpathy/char-rnn>（`data/tinyshakespeare/input.txt`），2026-11-10 取得，sha256 `86c4e6aa…565ed`；文本是莎士比亚剧作（公有领域）。最后 10% 留作验证。第 7 周的 Transformer 和第 2 周的计数实验都用它，切分相同。
- **模拟**：其余全部（三臂螺旋、二次函数、高斯随机输入与权重、高斯两类问题、第 2 周的 A/B 字母序列），都在脚本里按种子生成。标签就在每个实验的标题下面。
- **参考运行**（`src/reference.json`）：numpy 实验在构建机上经引擎代码跑出（`test/make_reference.py` 可重跑）；PyTorch 实验在 MacBook Air M5（PyTorch 2.15，MPS）上经同一引擎跑出，记在 `src/reference_mac.json`，再由 `make_reference.py` 并进去。每条都写明在哪、何时测的，以及跑的代码的 sha256（和页面发给引擎的那份一致）。
  - Transformer 的三条（quick / default / nopos）是一个任务里连着跑的（每次之前把 PyTorch 的种子重置为 1），数字由引擎的原始回复转出，没有手抄；那次引擎是自己从 char-rnn 仓库读的文本（日志第一行），和页面随任务发去的是同一份（两边算出的 bigram 基线逐位相同：2.4818894321158234）。
  - autograd 那一条起初是从 Mac 的运行结果手抄的（曲线只留了十个点，没有决策区域图）；当天晚些时候用 `test/mac_reference.py` 在同一台 Mac 上重录，现在和 Transformer 的三条一样由引擎的原始回复转出，代码的 sha256 核对过。两次的计时：宽 32 时 GPU 比 CPU 慢 7.5 倍和 6.2 倍，宽 2048 时快 1.8 倍和 1.5 倍；页面显示的是重录的那一次。
- **换种子的运行**（`test/mac_seeds.json`，不显示在页面上）：同一台 Mac、同一份代码（sha256 相同），2026-11-10 又跑了种子 2 和 3。300 步：2.242、2.235（种子 1 是 2.259）；2,000 步：1.578、1.577（种子 1 是 1.576）；去掉位置表（种子 2）：1.644（种子 1 是 1.663）。三道 Transformer 题的答案在这些种子下都不变；“去掉位置表”只有两对运行，页面上照实这么说。种子 3 的“去掉位置表”被时间预算截断，没有记。
  - **速度**：参考运行那一次是每秒 19.6 步（2,000 步 102 秒），第二次同一台机器只有每秒 8.5 步（235 秒），原因没有查明。所以页面写的是“2 到 4 分钟”，预算从 300 秒提到了 600 秒。

## 样本为什么这样做（铺开其余九周时照着做）

1. **先动手，后命名**。每个单元开头是一张要读者自己拨的图；笔记随后才给读者刚发现的东西起名字、给证明。
2. **四问是整个单元的纲**（想干什么 / 为什么可以这么做 / 为什么要这么做 / 有什么结果），放在单元开头的框里，各节各答其中一问的一部分；不是每个定理配一套。
3. **每条陈述标明它是哪一种**：定理或命题（在此证明或给出处）、启发式论证、经验事实、有争议。证明要么完整，要么写明是 sketch，一律折叠。有争议的地方并列各方，不下结论。
4. **实验先预测再运行，由这次运行自己的数字判定**。一个预设只问一个数能回答的问题，答案最好让认真的读者也意外；解释要说出机制，并指回笔记里证明它的那一节。选项的分界要离开数字可能落到的范围：每个 numpy 预设都换过 40 个随机种子，落在同一个选项里才算数；解释里出现的每个数都要能在这次运行或参考运行里对上。
5. **不抄课程材料**：只列主题、给链接、沿用记号。助教在没有笔记的周里明说自己凭一般知识回答。

## 设计目标（独立试玩时不给试玩者看）

- 整页：读者能说出“这是一门课的学习页：读、问、训练三步；每个实验先预测，再用运行结果检验”。
- 第 1 周的图：读者自己发现“拟合就是选数；规则（梯度下降）能替你选，但可能停在不对的地方”。
- 第 4 周的图：读者自己发现“陡的方向限制了步长，平的方向于是很慢；动量能改善”。
- 第 7 周的图：读者自己发现“注意力是可微的查表：锐 → 查表，平 → 平均；查询的长度等于锐度”。
- 第 1 周实验：读者发现“手写的反向传播和数值微分一致到舍入误差；全零初始化学不动；步长过大学不动”。

{"mcp": {"servers": [{"server": "host:mllab-engine", "tools": ["info", "run_start", "run_upload", "run_events", "run_cancel"]}]}, "sample": {}, "db": {}, "user": {}, "downloads": true}

### 第一轮（2026-11-10）

**判定：结论和设计目标一致。** 它自己说出来的（报告 A 段）：

| 设计目标 | 它的结论 |
|---|---|
| 整页：读、问、训练三步；先预测再用运行检验 | “play with a figure, read labelled statements with folded proofs, ask a tutor about any line, then predict the outcome of a training run, run it, and learn whether the prediction held and why” |
| 第 1 周的图：拟合就是选数；规则能替你选，但可能停在不对的地方 | “a sum of ReLU hinges fits a curve; gradient descent does the fitting and can stall” |
| 第 4 周的图：陡的方向限制步长；动量能改善 | “blow-up just above eta x kappa = 2 … momentum cut 76 steps to 18” |

### 第二轮（2026-11-10）

换了一个新的试玩者，试的是第一轮改完之后的构建（当时的 `index.html`，sha256 开头 `2f21fbf5`；分支后来整理成一个提交，那个状态不单独留在历史里）。提示词只有：页面的网址、“把它玩一遍”（电脑和手机宽度各一遍）、读者是谁、怎么开浏览器、测试构建的两处不同、要交回的四个问题。没有设计目标，没有要走到的清单，没有玩法提示。

- `node test/e2e.js [截图目录]`（目前 166 项；第 2 周起每写一周加几项，通用的检查见 `weekNotes`、`weekRun`、`weekRef`）：用替身运行时（`test/fake_claude.js`：助教是固定回答，数据库在内存里，引擎是真的）把页面按读者的路线走一遍——动手图（拖折点、梯度下降看得见地走）、节的链接和目录、后退回到离开的位置、选中提问、深入、Enter 发送追问、重复的提问打开原来那条、预测并运行、判定滚进视野、回到答过的题、没预测就看结果、历史和对比、改脚本后变成自由运行、改坏脚本看报错行、让助教改脚本、重载后回到原处且数据还在、引擎说明先讲用途、引擎没有 PyTorch 时改给参考运行、Mac 上录的参考运行、带数据集的任务分块送到引擎且脚本读到的文本逐字节一致；再在手机宽度（横向滚动的小标、用真实的触摸事件拖折点和滑动页面、代码行号、触屏上 Enter 换行）和“没有任何 Claude 能力”时各查一遍。

- `node test/serve.js [端口]`：同一个替身运行时，起一个本地网址，手动试。
- `python3 test/run_local.py src/experiments/<脚本>.py [参数=值 …]`：不经页面，直接经引擎代码跑一个实验。
- `python3 test/mac_reference.py job|record|check …`：录 PyTorch 实验的参考运行（构建机没有 PyTorch）。`job` 生成一个把若干预设连着跑的任务（每个预设之前重置所有种子），交给 Mac 上的引擎；`record` 核对跑的确实是仓库里的代码，再把引擎的回复写进 `src/reference_mac.json`；`check` 用一个 numpy 实验验证“连着跑”和“单独跑”逐位相同。
